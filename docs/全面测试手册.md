### A.2 质衡主平台

```text
1. 建库 qualitest（空库即可；已有脏库见下方「重置空库再跑 V1」）
2. 启动后端：Flyway 对空库自动执行 V1__baseline.sql（含内置项目模板、精简后的 6 条 AI 快捷提示词）
   不要用根目录 sql/qualitest_*.sql 当升级路径；那是备份导出。
3. 确认 qualitest-admin/.../application-dev.yml 库账号 / Redis 可用
4. 根目录：mvn clean package -DskipTests  或  qualitest.bat / qualitest.sh
5. 前端：cd qualitest-ui && pnpm install && pnpm dev
6. 浏览器：http://localhost:5173  →  admin / admin123
```

**重置空库再跑 V1**（本地开发；改过 V1 或要吃到最新种子时用）

> 只删业务表不够：Flyway 认 `flyway_schema_history`。`sql/reset_business_data.sql` **不会**重跑 V1，也 **不会**刷新 `ai_prompt_template`。  
> **只** `DROP DATABASE` 也不行：连接串仍指向 `qualitest`，启动连不上。

```sql
DROP DATABASE IF EXISTS qualitest;
CREATE DATABASE qualitest
  DEFAULT CHARACTER SET utf8mb4
  COLLATE utf8mb4_general_ci;
```

然后**再启动**质衡后端。空库 + `spring.flyway.enabled=true` 会自动执行 `V1__baseline.sql`。生产禁止这么干。

## B. Cursor 自动测试（Agent 逐步清单）

> 由 **Agent + IDE Browser MCP**（及可选 qualitest MCP）代点、代查。打勾：Agent 跑通或你亲自点过。失败记 §F。  
> 业务提示正文以 [ai-test-flow-prompts.md](../../qualitest-demo/docs/ai-test-flow-prompts.md) 为准；下表只列场景 ID + 意图 + 期望，避免双份漂移。



### B.0 分工与硬规则


| 谁             | 负责                                                                                                    |
| ------------- | ----------------------------------------------------------------------------------------------------- |
| **你**         | 起服务；**T1.3 IDEA 插件上传 demo 业务 API**；可选 RustFS / LLM Key                                                |
| **Agent**     | 浏览器代点（含产品 Staging ✓ / 保存 / Run）、截图、调 MCP、按 T1→T2→T3 验收并填结果；**发现产品 bug 则修代码后人可复现重测**。**不等** Cursor 审批卡 |
| **半自动 / 可跳过** | LLM Key、qualitest MCP Token、RustFS、Compose 一键栈                                                        |


**Agent 必须遵守**

1. 先确认端口再开浏览器；连不上就停，不空转。
2. 每小步：`browser_take_screenshot`（或等价）+ 标明 **通过 / 失败 / 跳过**。
3. iframe 点不到 → 记阻塞，改走 Swagger / curl / 调试台（仅作该步诊断；**T2 画布项仍须画布过**）。
4. 开启「允许还原被测数据」后：**同一环境串行跑**。
5. 写库场景前先加载对应场景（demo-ui 或 `POST /web/test/scenario/load/{id}`）。
6. 同一操作连续失败 ≥4 次 → 停手汇报。
7. 改画布走 Web **AI 助手 → Staging 确认 → 保存**；qualitest MCP **只读**。登录口令等优先素材库（Web AI `upsert_asset_variables` 提案 → 聊天侧确认后落盘 + `{{asset.*}}`），勿反复 flowSeed 占位。
8. **严格遵守 §B.0.1**（人可复现）；违反则该条勾选作废。
9. Staging 删除类：点 **✓ 确认删除** 即落盘删除（无二次弹窗）；自动化勿对 Staging 边按键盘 Delete。图乱则 Staging 全部 ✕ 或新建流重来。
10. **禁止空白画布当验收**：顶栏黄条「nodes 为空…」= 库里仍是新建空图（`nodes: []`）。AI Staging **未全部 ✓ 并保存**前，画布本来就是空的；**不得**把空图画布、空图保存、空图 Run 当作 T1/T2 通过。须 Staging 清零 → **保存后画布有节点** → 再 Run。
11. **画布展示不全**：先关挡着的 AI/属性侧栏，再 **拖拽画布**、点 **小地图** 聚焦，或点 **适应视图** / 缩放，把目标节点·边·Staging ✓ 挪进可视区后再点；禁止 `force` 点视口外或被挡住的控件。
12. **登录与 token 复用**（详见 **T1.8**）：主流 **Start → Subflow(登录子流)**，业务 HTTP 只用 `{{flow.token}}` / `{{flow.adminToken}}`，**勿**再插登录 HTTP。推荐登录子流内 **Condition**：`flow.token` 存在且探活 HTTP 200 → 跳过登录；否则走登录 HTTP（过期/无 token 会重登）。**引擎暂无**业务 401 自动续期；跨 Run 每次新上下文，探活分支才能省登录。双端同图须两套子流、两套 extracts，禁止覆盖同一 `flow.token`（Staging 硬拦 `AUTH_LOGIN_FLOWKEY_COLLISION`）。客户端多为 `$.data.token→token`，管理端 `/login` 多为 `$.token→adminToken`。画布 HTTP 应显示凭证作用域；抽错名红字。flowSeed 可预置 token 调试，禁止 flowSeed 塞口令。
13. **项目模板**：新建项目须至少勾一套模板（商城 Demo 建议「管理端 Bearer」+「客户端 Bearer」）；模板负责 Profile + **预制登录口**；**业务 API 以 T1.3 插件上传为准**（method+path 与预制重复则跳过）。免登 = 预制 `apis[].authConfig.mode=none`。详见 **T1.2**。
14. **造流会话**：同对话从零搭长流易 explainOnly（§F #17、§G.1）；**新建对话 + 短提示 + 显式 API id**。助手气泡「本轮未提交 Staging」= 未落盘。
15. **不等 Cursor 审批卡**：产品 Staging ✓ 由 Agent 点。禁止再弹原生批准卡；被拦则换路，仍拦则记 §F 后测下一项。验证码若开着，T1.1 记阻塞并停。

浏览器工具顺序：`browser_tabs` → `navigate` → `lock` → 交互 → 关键步 snapshot/截图 → 结束 `unlock`。  
质衡 MCP 可并行：查 `testFlowId` / 失败现场；浏览器改画布与点 Run。

### B.0.1 人可复现测试铁律（重点）

> **目的**：冒烟要证明「真人用户按产品 UI 能走通」；Agent 只是代点。若用控制台改 store、直接改库、或只调 demo API 刷绿，**对验收没有意义**，还会掩盖产品 bug。



#### 允许（人手也能做）


| 动作                                                           | 说明                                   |
| ------------------------------------------------------------ | ------------------------------------ |
| 浏览器点击 / 输入 / 选场景 / 保存 / Run                                  | 有头浏览器，用户可盯着看                         |
| 质衡 **AI 助手** 发提示 → Staging 逐项 **✓ 确认 / ✕ 取消** → 保存           | 与真人造流同一路径                            |
| AI 建议的 **删节点 / 删边 / 删场景**：点 Staging **✓ 确认删除**（唯一人工确认，无二次弹窗） | 拒绝用 ✕；勿对 Staging 边按键盘 Delete 当「确认删除」 |
| 画布展示不全时：**拖拽画布**、点 **小地图**、**适应视图** / 缩放                     | 与人手调视口同一路径；先关挡着的侧栏                   |
| demo-ui 或管理 API **加载 / reset 场景**                            | 产品提供的测试支撑，人手也会点                      |
| 调试台逐步调接口                                                     | 人手可用；可作诊断，**不能单独当作 T2「画布流」勾选依据**     |
| 素材库选文件上传、HTTP 节点填 `{{asset.*.storagePath}}`                  | 测参文件产品路径                             |
| 修 **产品代码 / SQL 种子 / 文档** 后，再按上表重测                            | 正规闭环                                 |
| 截图、Run 详情、§F 记现象                                             | 证据                                   |




#### 禁止（人手做不到或等于作弊）


| 禁止                                                         | 反例                                                |
| ---------------------------------------------------------- | ------------------------------------------------- |
| `page.evaluate` / 控制台改 **Pinia / Vuex / 内存图**              | 拒幽灵边、改 `pendingEdges`、直接 `markConfirmed`          |
| 直接 **UPDATE 库里的** `graph_json` **/ 跑批 SQL「修图」** 冒充 UI 造流成功 | 除非用户明确要求修数据脚本，且仍须 UI 重跑验收                         |
| 用 **curl/脚本只打 8081** 勾选 T2 画布相关项                           | API 绿 ≠ 画布/Staging/Run 绿                          |
| 为过断言 **悄悄改断言期望或跳过节点** 却不修引擎/不记 §F                          | 掩盖缺陷                                              |
| 点击被侧栏挡住或落在视口外仍 `force` 点、用户看不见的「幽灵操作」当成功                   | 应拖拽画布 / 点小地图 / 适应视图 / 缩放，使人也能点到                   |
| **空白画布 / 空** `nodes` **冒充造流成功**                            | 新建流默认空图；Staging 未确认保存则刷新仍空。须保存后画布可见节点再勾选          |
| 节点上只填绝对本机路径冒充「产品测参路径已通」                                    | 产品主路径是素材库上传 + `{{asset.*.storagePath}}`；绝对路径仅调试兜底 |




#### 卡住时怎么做（正规顺序）

```text
1. 截图 + 写清：UI 上人手下一步会点什么、点了发生什么
2. 判断：操作问题（没找到按钮） vs 产品缺陷（点了也不对 / 无法完成）
3. 产品缺陷 → 修代码（或记 §F 阻塞）→ 重启如需 → 从同一 UI 步骤重试
4. AI 造流出错（幽灵 start 边、非法断言运算符、不支持的 JsonPath）→
   用人可点的方式：Staging ✕ 取消坏项 / 让 AI「修复本节点或重生成」/ 属性面板改规则
   → 禁止用 store 手术让边「假装」灌进画布
5. 简单 bug 直修；复杂先写方案再改（能力缺口类）
```



#### T2 / 画布项勾选口径

- **可勾**：该用例对应测试流在质衡画布上 **Staging 已清零（若有）→ 已保存且画布非空（有节点）→ Run 终态符合期望**，证据含截图或 Run 时间。  
- **不可勾**：仅 demo API / Swagger / 临时脚本通过。可在备注写「API 曾绿，画布未验」。  
- **不可勾**：顶栏仍提示「nodes 为空」、画布无节点、或只建了空流名未完成 Staging→保存。  
- **推荐造流**：提示集对应段落 → AI 助手生成 → 用户（或 Agent 代点）确认 → **保存确认有节点** → Run；顺带测画布与 AI Staging。

#### T1.2 新建项目 + 项目模板（门禁 · §F #21/#24 回归）

> **顺序**：建项时**最先**勾项目模板（Profile + **预制登录口** + 可选 **预制参数/测试流**）；**购物车 / 下单等业务 API 不在模板里**，见 **T1.3 插件上传**。  
> **产品口径**：一行模板 = 一条 Profile；Apply 时生成新 `id` 写入项目 `auth_config.authProfiles`，并按 `templateApis[]` 插入预制接口（已有 method+path 跳过）。`templateParams` / `templateFlows` 可空；有登录流时从 extracts 派生 `credentialApi` 与托管头（`{{asset.*}}` / `{{flow.*}}`）。登录口免登 = `mode=none`。

1. **项目模板页**（菜单「项目模板」/`testProjectTemplate`）
  - 可见内置：**RuoYi Bearer**、**RuoYi Session**、**客户端 Bearer**、**管理端 Bearer**
  - 内置模板只读；可「克隆」为自定义模板（名称未删除范围内唯一）
  - 查看/编辑以**表格列出，按钮弹框打开请求/响应工作台**展示预制接口；内置只读，克隆后可改
2. **新建项目**（建议名「全面测试」；或用已有 demo 项目则跳到步骤 3 校验）
  - 不勾选任何项目模板 → 表单拦截「请至少勾选一套项目模板」
  - 勾选「管理端 Bearer」+「客户端 Bearer」（或至少 RuoYi Bearer）→ 创建成功
3. **项目设置 → 鉴权**

#### T1.8 登录子流（门禁 · token 复用）

> **目标**：T2 及后续主流**不再重复写登录 HTTP**；同一 Run 内 token 由子流产出，业务节点托管 Bearer。  
> 勾项目模板且模板带预制登录流时，项目内应已有「{模板名} 登录」等流；**优先挂该子流**，不必再从平台模板 fork。若无预制流，仍可「从平台模板创建」Bearer 登录。**无官方「401 自动续期」**，过期靠子流内 **Condition + 探活** 或每次 Run 重登。

1. **确认或创建登录子流**
  - 建项勾模板后：打开测试流列表，确认已有如 `客户端 Bearer 登录` / `管理端 Bearer 登录`
  - 若无：画布「从平台模板创建」→ 选 **Bearer 登录**，再绑登录接口与 extracts
2. **绑定与抽取（预制流已绑则可跳过）**
  - HTTP：客户端 `POST /api/account/auth/login`；管理端 `POST /login`
  - Body：`{{asset.clientAuth.*}}`（T1.7）或接口测值
  - Extract：对齐模板流（客户端 `$.data.token` → `token`；管理端 `$.token` → `adminToken`）
3. **（推荐）探活再登录 — Condition 分支**
  - 子流 **Start 后** 加 **Condition**：左值 `flow.token`，运算符 **exists**
  - **真分支**：可选 GET 个人资料 / `getInfo` 探活 → 200 则 **End**（跳过登录 HTTP）
  - **假分支**（无 token / 探活非 200 / 过期）：走登录 HTTP → End
  - 说明：每次 **新 Run** 上下文为空，除非 flowSeed 预置 token；探活分支才能在「token 仍有效」时省登录
4. **主流引用**
  - 打开或新建 `smoke-S01`（T1.10）：**Start → Subflow(**登录子流**) → 业务 HTTP…**
  - 业务 HTTP 使用 Profile 托管 Bearer；**不要再插登录 HTTP 节点**；AI 提示优先用已有登录子流
5. **画布凭证（回归 §F #7/#24）**
  - 登录子流 / 后续业务节点可见 `**flow.token**`（管理端子流则用 `**flow.adminToken**` + `$.token`）
  - （可选）顶栏 **「刷新鉴权头」** → 提案进 Staging → ✓ → 保存
6. **验证**
  - Run `smoke-S01`（或仅子流+一条业务 GET）→ 终态通过
  - （可选）同一 token 未过期时再 Run 一次：探活分支应跳过登录 HTTP（Run 详情时间线可见）

- [ ] 登录子流已存在（模板种子或平台模板 fork）；output / extract 对齐端别

### G.4 造流与鉴权铁律（汇总）

1. **鉴权**：新建必勾模板（**T1.2**）；业务 API **T1.3 插件**；免登 = 预制 `mode=none`；抽凭证读 Profile 托管头占位符 + `credentialApi`（[project-summary.md §4](./project-summary.md)）。
2. **Token / 子流**：主流 **Subflow 登录**（**T1.8**）；客户端 `{{asset.clientAuth.token}}` + `$.data.token`；管理端 `{{asset.adminAuth.token}}` + `$.token`；推荐 Condition 探活再登录；双端同图两套子流，禁止同 key 覆盖。
3. **失败路径**：场景字面量 + 「预期业务拒绝」；成功路径才用素材库 `{{asset.*}}`（[flow-variables-and-values.md](./flow-variables-and-values.md)）。
4. **退款 apply**：须 `items`（可先 preview 提取）；无 `/apply` 路径特例硬拦。
5. **长流造流**：新对话 + API id；「本轮未提交 Staging」= 未落盘（[ai-staging.md](./ai-staging.md)）。现场问题记 §F；通用疑问见 [faq.md](./faq.md)（非冒烟清单）。
