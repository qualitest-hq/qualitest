# 全面测试（T1→T2）未修复项

来源：本轮《全面测试手册》验收现场（约 2026-08-16）。**只收录仍未产品闭环的问题**；已关闭项见手册 §F #1–#23。

---

## 一、适合做优化（有明确产品/提示侧落点）

### 1. 管理端登录提取路径与提取名（§F #24）

- **现象**：AI 反复把管理端 `/login` 写成 `$.data.token`（客户端习惯），Run 时报 `{{flow.token}}` 未定义。若提取名写成 `adminToken`，Staging 登录口校验要求必须产出 `flow.token`，✓ 确认被挡。
- **现场做法**：字面量 `admin`/`admin123` + 画布手改 `expr=$.token`、`name=token`。
- **可优化方向**：
  - API `loginHint` / designHints：管理端写明 `$.token`；
  - Staging 或造流归一：识别 RuoYi 登录响应结构；
  - 双登录流允许「第二段登录」提取别名，或明确「后登录覆盖 `flow.token`」的模板。

### 2. 同会话长提示仍易 explainOnly / 步数吃紧（§F #17 已缓解、未根治）

- **现象**：同对话多轮从零搭长流时，仍可能大量拉接口详情后只出方案、不出 Staging；或步数将尽才催 submit。
- **现场做法**：新建对话 + 短提示 + 显式 API id。
- **可优化方向**：进一步压低 `get_api_details` 体积、强制「短流必 submit」门禁、按任务类型动态加步数。

### 3. OpenAPI 把 `BaseEntity.params`(Map) 同步成 query（#23 仅治标）

- **现象**：列表类接口 query 含 `params`；空串发出后被测端 500。本轮已在跑流侧**跳过 blank query**（#23），但资产里仍挂着无意义的 `params` 参数行。
- **可优化方向**：导入/同步时过滤复杂类型（Map/Object）query，或默认 `_enabled=false`；比仅靠运行期跳过更干净。

### 4. 失败路径 / 字面量凭证：AI 仍爱写 `{{asset.*}}`

- **现象**：管理端或失败账号体偶发写成 `{{asset.adminAuth.*}}` / `{{asset.clientAuth.*}}` → 占位未定义或测错账号（§F #22 已有模板缓解，现场仍复发）。
- **可优化方向**：造流校验「登录 body 禁止未解析 asset」；失败路径模板默认字面量；Staging 对未定义占位硬拦。

### 5. 退款申请 `items` 必填 vs AI 只写 orderId

- **现象**：R1 仅 `orderId` 申请 →「退款明细不能为空」。从预览提取 `items` 时，断言左值带 `.items` 曾撞 schema 关键字校验，Staging 难落盘。
- **现场做法**：apply body 字面量 `orderItemId`+`refundQuantity`（如 8003/8004）。
- **可优化方向**：退款 API designHints「apply 必填 items」；预览→申请的数组提取模板；断言路径关键字转义/白名单。

### 6. AI「修复」叠 Staging 易多入口 / 脏图

- **现象**：同流多次修复确认后，偶发双开始节点或未确认项卡死，只能「仅保存已确认」导致半截图。
- **可优化方向**：confirm 合并时校验唯一 start；修复 diff 默认「替换子链」而非叠加；未确认项一键驳回并清理。

### 7. 客户端 + 管理端同流的 token 作用域

- **现象**：Staging 要求登录口提取名必须是 `token`；E2 单流若先客户端再管理端，只能覆盖同一 `flow.token`，否则管理端节点无法 ✓。单流端到端因此更脆，本轮 E2 改为 S03 申请 + S06 审核两段。
- **可优化方向**：多凭证作用域（如 `flow.clientToken` / `flow.adminToken`）+ 登录口校验识别「已声明的登录提取」；或官方「双端接力」子流模板。

### 8. 登录口免登：用「开源/靶场项目模板」，不要靠全局 path 启发式

- **背景**：本轮曾为止血给 IDEA 插件加「内置免登 path 启发式」（看见 `/login` 等就标 `auth.mode=none`），与服务端 `BUILTIN_ANONYMOUS_AUTH_PATH_EXACT` 对齐。该方案把靶场常识抬成平台默认，误伤面大，**插件侧提交已撤回**。
- **不宜**：在扫描/跑流层继续加全局「猜免登 path」清单，并在插件与服务端各维护一份。
- **宜做**：内置常见开源/靶场**项目鉴权模板**（例如商城 Demo 双端 Bearer，已有 `dualBearerTemplate()` 雏形），把免登 path、`loginHint`、分端 Profile 一次写进项目配置；扫描只认**注解 + 项目 anonymousPath**；上传/新建项目时可选「套用某某模板」。
- **后续清理（可选）**：评估收窄或下线服务端全局 `matchesBuiltinAnonymousAuthPath` 运行期兜底，改为「仅模板写入的项目配置生效」。

## 二、不适合针对做优化（或应换赛道）

### 1. P2 基线商品无 cover/detail/video

- **性质**：demo 种子数据 / T3.1 媒体能力范围，不是质衡画布引擎缺陷。
- **建议**：跟 T3 媒体与 fixture 一起做；勿单独开「P2 产品优化」小单。

### 2. 场景必须 UI 加载、写操作须串行

- **性质**：靶场设计（seed/reset、状态机），不是平台 bug。
- **建议**：手册与提示集约定即可；不要为「免加载场景」改质衡主路径。

### 3. LLM 非确定性导致偶发坏 patch

- **性质**：模型行为方差；#17/#22/#24 类问题用提示与门禁兜底即可。
- **建议**：用回归夹具 + 提示集约束，而不是为每一次偶发输出开专项重构。

### 4. 浏览器 beforeunload / 离开未保存提示

- **性质**：防丢数据的正常行为；冒烟 Agent 被打断属操作节奏问题。
- **建议**：测法上「先保存再跳转」；一般不必改产品交互。

### 5. Agent/Playwright 点选 Staging 按钮的选择器细节

- **性质**：自动化实现细节（如紧凑 ✓ 的 class），不是终端用户路径。
- **建议**：留在冒烟脚本/规则里；不要当成质衡功能需求。

### 6. 环境同名「默认环境」一条 8081、一条 127.0.0.1

- **性质**：本地数据配置问题；选错则整轮跑偏。
- **建议**：种子/文档约定唯一默认；不必做复杂「智能选环境」功能，除非产品本身要做环境去重 UX。
