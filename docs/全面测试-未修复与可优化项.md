## 一、适合做优化（有明确产品/提示侧落点）

### 1. 管理端登录提取路径与提取名（§F #24）— **已关闭（2026-08-17）**

- **关闭说明**：提取路径不猜——有 `loginHint` 或可用响应 schema 才写入/纠正；schema 为 Map/空则不编 JsonPath，留给跑流后 AI 修复。前后端去掉「单段自动补 `$.data`」。双端登录口认本端变量名（管理端 `adminToken` + `$.token`）；expr 仅在 hint/schema 能确定时硬拦。`get_api_details` 登录口补短 hint。未做运行期双路径试算、未自动套双端模板。
- **现象**（原）：AI 常把管理端 `/login` 写成 `$.data.token`（客户端习惯），Run 报 `{{flow.token}}` 未定义。提取名若写成 `adminToken`，现场 Staging 曾因「登录口须产出 `flow.token`」挡 ✓（与文档「管理端 → `adminToken`」不完全一致，属产品口径冲突）。
- **现场做法**（原）：字面量凭证 + 画布手改 `expr=$.token`、`name=token`。

**多角度方案**

| 角度 | 做法 | 收益 / 代价 |
| --- | --- | --- |
| A. 资产 / 模板 | 管理端 Profile 写死 `loginHint`：`$.token → adminToken`；商城 Demo 项目模板一键写入；`designHints` 注明「禁止 `$.data.token`」 | 造流有据可依；需模板/种子覆盖存量项目 |
| B. 造流 AI | system prompt + Normalizer：path 命中 `/login` 且非 `/api/` 时强制建议 extracts；提交前改错 expr | 改动面中；依赖 path 约定 |
| C. Staging 门禁 | 统一口径：管理端登录口允许/要求 `adminToken`（与 `test-flow-nodes.md`、双端 Profile 一致）；误用 `$.data.token` 硬拦并给出一键修正 | **优先**：消掉文档与现场校验打架 |
| D. 运行期兜底 | 登录响应同时试算 `$.token` 与 `$.data.token`（仅登录口） | 止血快，但掩盖配置错误，建议仅 soft warning |
| E. UX | 提取行旁「按 loginHint 填充」按钮；失败 Run 详情链到「改提取」 | 人不靠 AI 也能修 |

- **不宜**：继续全局「凡登录都叫 `token`」而文档写 `adminToken`；不宜只靠冒烟手册口头约定。

### 2. 同会话长提示仍易 explainOnly / 步数吃紧（§F #17 已缓解、未根治）

- **现象**：同对话多轮从零搭长流，易狂拉接口详情后只出方案、不出 Staging，或步数将尽才催 submit。
- **现场做法**：新建对话 + 短提示 + 显式 API id。

**多角度方案**

| 角度 | 做法 | 收益 / 代价 |
| --- | --- | --- |
| A. 工具层 | 继续压 `get_api_details`（已有批量/截断）；按「造流 vs 修复」返回不同详略；禁止同会话重复拉同一 apiId 全文 | 直接省步数 |
| B. Agent 策略 | 剩余步数 ≤N 强制只能 `submit_*`；「从零搭」任务模板默认 maxSteps 更高；检测到 explainOnly 自动追问一轮「请 submit」 | 体验好，要防死循环 |
| C. UI | 摘要区常驻「本轮未提交 Staging」+ 一键「请 AI 落盘」预设 prompt；长对话提示「建议新开对话」 | 零后端风险 |
| D. 产品流程 | 官方「短流积木」：登录子流 / 退款审核子流，主对话只拼积木 | 治本但要模板库 |
| E. 测法约定 | 手册铁律保持：新对话 + API id（现状） | 不改代码也能稳 |

- **不宜**：无限加大 maxSteps 掩盖工具过肥。

### 3. OpenAPI 把 `BaseEntity.params`(Map) 同步成 query（#23 仅治标）

- **现象**：列表接口 query 含 `params`；空串曾导致被测端 500。跑流已**跳过 blank query**（#23），资产行仍在。

**多角度方案**

| 角度 | 做法 | 收益 / 代价 |
| --- | --- | --- |
| A. 导入/同步 | schema `type=object` / Java `Map` → 不进 queryParams，或默认 `_enabled=false` 且 UI 灰显「框架内部参数」 | 根治脏资产 |
| B. 跑流（已做） | blank 不发送（#23） | 已止血；保留作安全网 |
| C. 调试台 / 画布 | 参数表支持「禁用框架 params」；批量清理项目内名为 `params` 且空值的 query | 存量可修 |
| D. 被测约定 | demo/RuoYi 文档说明勿把 `params` 当业务 query | 治标不治本 |
| E. OpenAPI 生成 | 若用 springdoc，排除 BaseEntity.params | 改靶场/生成器，非质衡主仓必做 |

- **不宜**：删掉 #23 运行期跳过却不同步清资产。

### 4. 失败路径 / 字面量凭证：AI 仍爱写 `{{asset.*}}`

- **现象**：失败账号或管理端登录体写成 `{{asset.clientAuth.*}}` / `{{asset.adminAuth.*}}` → 占位未定义或测错号（§F #22 模板已缓解，仍复发）。

**多角度方案**

| 角度 | 做法 | 收益 / 代价 |
| --- | --- | --- |
| A. 快捷模板 | 「预期业务拒绝」默认 body 字面量 + 关业务 Code；造流选失败场景时自动套用 | 已有雏形，加强默认 |
| B. 资产策略 | 场景测值 vs 素材库：失败用例优先场景字面量；禁止把主测号素材绑到 F01 类流 | 产品规则清晰 |
| C. Staging / submit 门禁 | 登录类 HTTP：body 含未定义 `{{asset.` 硬拦；提示「失败路径请用字面量」 | 高性价比 |
| D. AI prompt | 失败路径关键词（停用/拒绝/F0x）触发「严禁 asset」附言 | 软约束 |
| E. Run 诊断 | 占位未定义时错误码区分「登录体用了 asset」并给修复 patch 预设 | 修得快 |

- **不宜**：为方便测试在素材库塞「停用账号密码」当默认 clientAuth（易污染成功路径）。

### 5. 退款申请 `items` 必填 vs AI 只写 orderId

- **现象**：仅 `orderId` apply →「退款明细不能为空」。预览提取/断言左值带 `.items` 曾撞 schema 关键字硬拦，Staging 难落盘。
- **现场做法**：apply 字面量 `orderItemId` + `refundQuantity`。

**多角度方案**

| 角度 | 做法 | 收益 / 代价 |
| --- | --- | --- |
| A. designHints | 退款 apply API 写明「items 必填；可先 preview」；示例 body | 造流直接看见 |
| B. 造流模板 | 官方两节点：「预览 → 提取可退明细数组 → apply」或「字面量 items（场景种子 ID）」二选一快捷块 | 人/AI 都省事 |
| C. 断言门禁 | JsonPath 段名 `items` 与 schema 关键字冲突时改白名单/转义（`['items']`）；硬拦文案写清正确写法 | 解 Staging 卡死 |
| D. AI Normalizer | apply 无 `items` 时自动补空数组并 warning，或拒绝 submit 并提示补明细 | 防空跑 |
| E. 靶场种子文档 | 提示集写明 S03→8003/8004、S05→8006 等 orderItemId | 不改引擎也能测 |

- **不宜**：把 apply 改成「无 items 即全退」除非业务真如此（会掩盖测例意图）。

### 7. 客户端 + 管理端同流的 token 作用域 — **已关闭（2026-08-18）**

- **关闭说明**：画布 HTTP 节点显示将使用/产出的 `flow.token` / `flow.adminToken`，托管头串端或登录抽错名红字。不同 method+path 的凭证口写出同一 flowKey 时硬拦 `AUTH_LOGIN_FLOWKEY_COLLISION`。造流 prompt：同端只登录一次；双端同图须两套登录、两套 extracts，禁止覆盖同一个 `flow.token`。**未做**官方登录子流积木（方案 B）；场景切分仍可用。
- **现象**（原）：双端同流时提取名/托管头易打架；本轮 E2 拆成 S03 申请 + S06 审核。文档已描述 `token` vs `adminToken` 分端。登录口认本端变量名已随 §1 关闭；同流双套托管头 / 单图画布仍未闭环。

**多角度方案**

| 角度 | 做法 | 收益 / 代价 |
| --- | --- | --- |
| A. 统一产品口径 | 严格双端：客户端 `flow.token`，管理端 `flow.adminToken`；托管头按 pathPrefix 选 Profile；登录口校验认「本端变量名」 | 与 `dualBearerTemplate` / 节点文档对齐 |
| B. 子流模板 | 「客户端登录子流」「管理端登录子流」官方积木，主流程只引用 | E2 单图画布更稳 |
| C. 场景切分（现状） | 提示集允许 S03→S06 两段验收 | 已验证可用 |
| D. UX | 画布显示「当前节点将使用的凭证变量」；冲突时红字 | 降低误配 |
| E. AI | 同流出现两种登录 API 时强制两套 extracts + 两套 Bearer 变量 | 依赖 A 的口径一致 |

- **不宜**：长期「后登录覆盖同一个 `flow.token`」当官方模型（难读、难断言）。

### 8. 登录口免登：用「开源/靶场项目模板」，不要靠全局 path 启发式 — **已关闭（2026-08-18）**

- **背景**：曾为止血给 IDEA 插件加「内置免登 path 启发式」，**插件提交已撤回**。服务端仍有 `matchesBuiltinAnonymousAuthPath` 运行期兜底（与项目 `anonymousPath*` OR）。
- **不宜**：扫描/跑流层全局猜 `/login`；插件与服务端双份清单；SQL 回填 Demo `auth_config`；自动给所有项目套双端；项目 `auth_config` 挂 `templateId`；本轮不做 Vue-Plus、`anonymousPathPrefix`、下线 `BUILTIN_*` 本身（空配置仍暂留）；不改 `test_project` / `test_project_api` 加列。默认模板不要再混 `/api/account/auth/*`（那是客户端模板的事）。

**已定产品口径（明天落地）**

- 新增平台表 `test_project_template`（Flyway `V1__baseline.sql`）。**一行模板 = 一条 Profile**。无 `template_key`；目录用主键 + 名称。勾选 = 按列组装拷进 `test_project.auth_config.authProfiles`（**新生成 `id`**，不回写模板 id）。跑流只读项目副本。
- 项目 `authProfiles` 仍是**数组**；删项目级 `defaultProfileId`。未命中 `pathPrefix` → **数组第一条**（勾选顺序；测本仓商城先勾管理端）。已有**同名** Profile 整份跳过。`method+apiPath` 跨条全局去重。
- 不再用项目级 `anonymousPathExact` / `anonymousPathPrefix`。预制接口走该条 **`apis[]`**（形状对齐 `test_project_api`，不写库主键）。免登认 `apis[].authConfig.mode=none`（只留 mode）。抽凭证挂 **Profile**：`credentialApi`（哪一口登录）+ `loginHint`（写入哪个 flow 变量）。同 path `/login` 靠 `loginHint.flowKey` 区分 `adminToken` 与 `token`。以后可往 `apis` 加 `GET /getInfo`（`mode=inherit`），不必改 schema。
- **预制参数**用现有 `testValueConfig.request.bodyExample`（调试默认登录 body）和 `requestConfig.body.json.example`（字段形状）；`responseConfig.responses[].example` 只作软嗅探。不要用 response 替代 `loginHint`。
- parse **读兼容**旧数组、旧 `header: {name,valueTemplate}`、旧 Profile 级 `loginHint`、旧 `apis[].authConfig.loginHint`（上提到 Profile）、旧 `anonymousPathExact`（path-only 的 none 接口）；**忽略**旧 prefix。normalize 写出数组 + 扁平头 + `credentialApi` + Profile.`loginHint` + `apis`（auth 不含 hint）。模板表 `apis` 里登录口仍可带 hint，apply 时上提。
- 新建必须至少勾一套；设置「从模板库添加」。模板库：内置只读可克隆，自定义 CRUD / 另存为（`template_name` 未删除范围内唯一）。仍可手加不在库里的 Profile。
- 选/加后按 `apis` insert `test_project_api`（对象列序列化成现有 JSON 列；`apiGroup` 点号逐级查找或创建；空则「默认分组」）。**已有 method+path 整条跳过，禁止改已有接口**。接口行 `auth_config` 只写 `{mode}`，不落 `loginHint`。`insertTestProject` 空配置拒绝；上传空配置仍种「RuoYi Bearer」。删除 `dualBearerTemplate()`，双端 = 追加管理端 + 客户端两条。

## 二、不适合针对做优化（或应换赛道）

下列**不建议单开质衡引擎专项**；若仍要动，只做「换赛道」级动作。

### 1. P2 基线商品无 cover/detail/video

- **性质**：demo 种子 / T3.1 媒体能力。
- **换赛道**：T3 媒体 + fixture + 种子字段；手册保持跳过即可。
- **不宜**：为勾 P2 改断言引擎或造假媒体字段。

### 2. 场景必须 UI 加载、写操作须串行

- **性质**：靶场状态机设计。
- **换赛道**：加强 demo-ui / 提示集；可选「场景加载」MCP 只读辅助（仍须人可复现）。
- **不宜**：质衡 Run 隐式改被测库绕过加载。

### 3. LLM 非确定性导致偶发坏 patch

- **性质**：模型方差。
- **换赛道**：提示集 + Staging 门禁 + 回归夹具（§1/2/4/5/6）；评测集固定 apiId 短提示。
- **不宜**：为单次坏输出做一次性格化硬编码。

### 4. 浏览器 beforeunload / 离开未保存

- **性质**：防丢数据。
- **换赛道**：测法「先保存再跳转」；Agent 统一 `dialog.accept`。
- **不宜**：关掉 beforeunload。

### 5. Agent/Playwright Staging 选择器细节

- **性质**：自动化实现。
- **换赛道**：冒烟规则/`data-testid`（若产品愿意加稳定钩子，属测试友好，非业务功能）。
- **不宜**：为 MCP 脚本改 Staging 视觉交互。

### 6. 环境同名「默认环境」8081 vs 127.0.0.1

- **性质**：本地数据。
- **换赛道**：种子只留一条默认；文档写死选 8081；可选 UX「重名环境警告」（轻量）。
- **不宜**：智能猜测 baseUrl 静默切换。
