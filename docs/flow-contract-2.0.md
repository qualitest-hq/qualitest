# 测试流契约 2.0（设计草案）

> **状态**：设计草案（**核心拍板已收束**）· 建议产品版本 **2.0.0**。  
> **产品切口**：**流契约 2.0 + 平台插件**同发大更新（不是「先发流、插件另版」）。  
> **范围**：入参 / 出参、入口形态、返回与收束、入口说明、与插件边界。  
> **本稿不做**：改代码、迁库、改画布实现。  
> **版本判断**：见 §8.2；§8.1 允许 Flyway 重做基线（不做 1.x 热升级）。

---

## 0. 用名（全文唯一）

| 中文 | 英文 / 符号 | 是什么 |
|------|-------------|--------|
| **入口** | **entry** | 图的开始节点类；一次 Run 只从一个入口进入 |
| 场景入口 | `scenario-entry` | 人跑 / CI / 套件 |
| 子流入口 | `subflow-entry` | 被父流调用 |
| HTTP 入口 | `http-entry` | 开放入站 |
| 协议入口 | `{protocol}-entry` | 插件贡献，如 `tcp-entry` |
| **返回** | **return** | 平台节点：定稿出参 `out`（瘦配置，见 §4.1）；按 `entryKind` **立刻写出/挂载**；**默认不结束路径** |
| **收束** | **settle** | 引擎概念（**非画布节点**）：路径走尽（真并行则 **join 齐**）后结束；写 Run；**不再二次写出**（开放/子流已在 return 做过） |
| **出参** | **`out`** | 运行时对象：`status` / `headers` / `body`；**回什么由它说了算** |
| **入参** | **`in`** | 运行时入参；形状挂在各入口上 |
| **入口说明** | entry doc / `doc` | 挂在**入口节点**上的可选 Markdown；给人看，不参与跑流 |
| **入口种类** | **`entryKind`** | `scenario` / `subflow` / `http` / 协议短名 |
| **入口节点 id** | **`entryNodeId`** | 本图具体哪个入口节点 |
| **触发源** | **`run.trigger`** | 谁发起的这次 Run（与 entryKind 正交；见 §2.1.0） |

角色：`entry` | `return`。  
类型（平台）：`scenario-entry` | `subflow-entry` | `http-entry` | `return`。

**不做**：必选的「成功/失败响应表 / 响应目录」。入口**不**声明回法清单；开放 HTTP 与子流都不硬要它。

## 1. 为什么要升到 2.0

1.0 把「怎么跑图」做起来了，但对外契约是拼出来的：

- 入参 / 开放入站挤在侧栏「流配置」
- 扁平 `flowOutputs` 和真正运行时 `out` 两套话
- 场景 / 子流 / HTTP 入口语义不同，却挤在同一块 meta 里

2.0 口号：

**契约进入口；回法看出参；说明手写可选；路径结束按 entryKind 收束；协议可插件。**

### 1.1 返回与收束

| 概念 | 做什么 | 图停不停 |
|------|--------|----------|
| **返回** | 定稿当前 `out`；按 `entryKind` **立刻写出/挂载**（开放回包、子流挂父） | **默认不停**，后面还能断言 |
| **收束** | 路径走尽（并行则 join 齐）；写 Run；开放/子流**不**再写出 | **停** |

- 进用入口；走到无后继即收束（并行先 join）。  
- 多入口共用中段；业务分道用 IF；**真并行**各臂可同时跑；入口差异用 `run.entryKind`。  
- **返回时立刻写出、图继续**（已拍板）：先回包/挂载，再断言；断言失败不影响已写出的内容。  
- **整次 Run 的 `return` 次数**（已拍板）：开放/子流恰好一次，场景零或一次；见 §2.2。

## 2. 目标图景

| 节点角色 | 干什么 |
|----------|--------|
| **场景入口** | 选环境、灌场景入参；可选写入口说明 |
| **子流入口** | 声明本流被调用时收哪些入参；**不**声明回法表 |
| **HTTP 入口** | 即开放入站（**无**「是否开放」开关）；method、path、请求格式、入参形状、环境；可选写入口说明 |
| **业务节点** | HTTP / 条件 / Assign / … |
| **返回** | 定稿 `out` 并立刻写出/挂载；默认不结束 |

路径自然结束 → **收束**。

平台基本项：入口、入参形状、出参 `out`、返回、收束、可选入口说明。  
插件：`{protocol}-entry` + codec + 登记该 kind 的收束。平台错包内置。

### 2.1 多入口

- 只有入口可作开始；一次 Run 只进一个入口。  
- 多 HTTP 入口：登记/路由唯一键 **method + path**（已拍板；不含 host/query）。  
- 多场景入口：**每个场景入口自带场景子集**（环境 + `inSeed`）；跑前选入口后再选该入口下的场景。不做流级共用大列表。  
- 子流入口：默认一图一个；多个时父节点指定进哪个。  
- 从入口应能走到无后继末端。  
- **新建流**：**完全空白**，不预置任何入口；用户自己拖场景 / HTTP / 子流入口（向导可后置，不强制落盘骨架）。

### 2.1.0 入口开始标识与触发源

开跑注入只读（均在 `run.*`，供 Condition / 脚本 / 占位）：

| 字段 | 含义 |
|------|------|
| `entryKind` | 从哪种入口进 |
| `entryNodeId` | 具体哪个入口节点 |
| `trigger` | **谁触发的这次 Run**（首版就要） |

`trigger` 建议枚举（落地可微调文案，须稳定短名）：

| 值 | 典型来源 |
|----|----------|
| `ui` | 画布人手点跑 |
| `ci` | CI 管线 |
| `suite` | 套件 |
| `http` | 开放 HTTP 握连接入站 |
| `mcp` | MCP `run_test_flow` 等 |
| `subflow` | 父流子流节点调起 |

与 `entryKind` **正交**：例如人手跑场景入口 → `entryKind=scenario` + `trigger=ui`；开放入站 → `entryKind=http` + `trigger=http`；CI 跑场景 → `entryKind=scenario` + `trigger=ci`。

Condition 示例：`run.entryKind`、`run.entryNodeId`、`run.trigger`。  
**收束 / 写出仍只看 `entryKind`**，不靠 `trigger`，不靠结束类节点。

### 2.1.1 旧「运行配置」

大一统侧栏退役：

| 1.0 | 2.0 |
|-----|-----|
| 场景 / inSeed | 场景入口 |
| 入参、`open`+path | **HTTP 入口**（有即开放，不再要 `open` 布尔）；子流入口只管入参形状 |
| 扁平 `flowOutputs` | **不再要流级对外字段表**；写出靠 `out`；子流在 **`return` 时整包挂载** `nodes.<子流节点id>.out`（父节点**不要** `outputs` 映射表） |

侧栏最多总览；跑前选入口/环境是运行动作。

### 2.1.2 说明给人对着看（不是从流里抽表）

- **不**从画布自动抽出「成功/失败响应表」当文档。抽也不全，还得备注。  
- **说明挂在入口节点上**（`data.doc` 或等价字段，可选 Markdown）：对接注意、changelog、举例……**不写也行**。  
- **不做**独立文档资源表；多入口 = 多篇，各挂各的节点。  
- 详情页：**主看当前入口的说明**；用户**切换入口**即换篇；旁路可只读展示该入口请求配置（method/path/入参树），不当「抽出来的完整 API 说明书」。  
- **分享深链（本次不做，前期记下）**：理论上详情 URL 应能带上入口（如 entryNodeId / method+path），打开即落在那一套说明；首版只做页内切换，不做分享链接。  
- **不做 OpenAPI（等）导出**：对接看入口说明即可（复制粘贴各篇，或让 MCP/AI 读图）；不维护、也不从「响应表」生成规格文件。

### 2.2 返回与收束

| 概念 | 作用 |
|------|------|
| **返回** | 定稿 `out`；按 `entryKind` **立刻写出/挂载**；**默认不结束** |
| **收束** | 走尽（并行 join 齐）→ 写 Run；**不**再二次写出/挂载 |

硬约束：

1. **回什么 = 出参 `out`**（status / headers / body）；不靠响应表选型。  
2. 一次 Run 一个入口；须能自然结束（或失败/平台错包中止）；**支持真并行**（多臂同时执行，收束前 join）。  
3. **`return` 时立刻按 `entryKind` 写出/挂载**，图继续；收束不再写第二遍。  
4. **整次 Run 的 `return` 执行次数**：  
   - **开放 / 子流**：**恰好一次**（少一次 / 多一次都不行）；  
   - **场景**：**零或一次**（不要求）。  
   不限于「同一条线」——并行各臂合计也算。  
5. **图上多个 `return` 节点何时合法**：  
   - **IF 互斥臂**：各臂可各有一个 `return`（运行时只走一臂 → 仍只执行一次）。  
   - **真并行域**：并发臂上**静态至多一臂**的可达子图含 `return`；两臂都带 → **挂图异常**。  
   - 同一条顺序路径上两个 `return`（含中间夹断言）→ **挂图异常**。  
6. **并行双末端合法**：各臂可各自走到尽头；不要求每条臂都经过 `return`（无 return 的臂只做事，写出/挂载由那唯一的 `return` 臂负责）。

### 2.2.1 典型画法

```text
顺序：
… → Assign 组 out → return（定稿 + 立刻写出/挂载）→ 断言 →（收束：只收尾）

IF 互斥（图上可有多个 return 节点）：
IF
├─ 成功 → return → …
└─ 失败 → return → …

真并行（整域合计一个 return）：
fork
├─ 臂A：旁路校验 / 准备工作 → 尽头（无 return）
└─ 臂B：组 out → return（写出）→ 断言 → 尽头
join → 收束
```

非法：并行两臂都带 `return`；或 `return → … → return`（同序第二次）。  
断言失败在 return 之后：客户端/父流**已收到**写出内容；本 Run 仍记失败。

### 2.3 协议插件

`{protocol}-entry` + codec + 登记收束；未登记则无法正常收束。

### 2.4 二进制（设想）

`return` 写出时对完整 `out` 做 codec；业务图尽量不碰裸字节。

## 3. 三层失败

| 层 | 含义 | 谁负责 |
|----|------|--------|
| **平台挂了** | path 未登记、图坏、槽满、跑崩、写出失败等 | 引擎 / 握连接内置错包（404/400/502/503…） |
| **业务结果** | 已进图；成功或业务失败 | 图内分支组不同 `out` + 返回（立刻写出/挂载） |

平台错包**不配在入口上**。入口只负责怎么接请求。  
业务鉴权失败（含 401）属**业务结果**，图内组 `out` + return；**不是**入口硬拦。  
要对人说清的业务码/状态 → 写在**入口说明**里，或靠前端/对接方自己看实际 `out`；**不**强迫维护机器响应表。

## 4. 出参与入参（无响应表）

### 4.0 出参 `out` 就是回法

| 字段 | 含义 | 谁写 |
|------|------|------|
| `out.status` | HTTP 状态（主要给**开放写出**用） | Assign / 脚本写入；**不是** return 节点配置项 |
| `out.headers` | 响应头 | 可写 |
| `out.body` | 正文 | 主写 |

写出/挂载时机：在 **`return`**（不是收束）。  
- **HTTP 入口写出**（跟现 `OpenInboundOutFlush`）：有啥 `out` 写啥；缺 `out.status` → **写出时**补 **200**；缺 Content-Type → 补 json（见下）。  
- **子流**：整包挂载当时的 `out`（含是否带 status，原样挂；**不**在 return 上补 HTTP 默认码）。  
- **场景**：无对外写出。

**响应 `Content-Type`（与现网一致，入口不选手填）**：

1. `out.headers` 已有 `Content-Type` / `content-type` → 用它；  
2. 否则默认 **`application/json;charset=UTF-8`**（平台错包同此）。  

要 XML/其它类型 → Assign 写进 `out.headers`，不在 HTTP 入口另开配置项。

### 4.1 返回节点（瘦配置）

**返回 = 打定稿戳 + 按入口立刻交付，不是小配置中心。** 回包内容仍由前面的 Assign / 抽取写入 `out`。

运行时：

1. 读取当前 `out`，记为「本路径定稿出参」（**不**在节点上补 `status`）。  
2. 按 `entryKind` **立刻交付**：**HTTP** → 写出（缺 status 则在**写出路径**补 200）；**子流** → 挂父 `nodes.<子流节点id>.out`；**场景** → 无对外写出（仅快照）。  
3. **不停**，继续往后走（断言等）。本 Run 若再执行到第二个 `return` → 异常（图校验应已拦）。

| 配置项 | 要不要 | 说明 |
|--------|--------|------|
| （节点本身） | 要 | 时间线可见的一步：定稿 + 立刻交付 |
| `label` / 备注 | 可选 | 如「支付成功」「余额不足」，方便人与 AI 读图 |

**首版不要：**

| 不要 | 原因 |
|------|------|
| `defaultStatus` 等 HTTP 专用项挂在 return 上 | status 缺省只在 **HTTP 写出**补 200；场景/子流用不上 |
| 绑定响应目录 / 响应 id | 不维护响应表 |
| 按字段树校验整份出参 | 要验用后面的 Assert |
| 灌示例 body | body 靠前面 Assign |
| 成功/失败角色章 | 成败看步骤/断言；子流执行到 return 就挂，与成败分离（§6.4） |

`data` 示意：

```json
{
  "type": "return",
  "data": {
    "label": "支付成功"
  }
}
```

图校验（与 §2.2 一致）：开放/子流须能保证整次 Run **恰好一次** return；并行域禁止多臂都带 return；IF 互斥臂除外。场景不要求 return。

### 4.2 入参（形状 vs 值）

对齐现状分工（`GraphInputField` / `inputSpec.fields` = 声明；`scenarios[].inSeed` = 取值），2.0 挂到入口上后仍分开：

| 放哪 | 有没有值 | 是什么 |
|------|----------|--------|
| **入口上的入参形状** | **无值**（或仅可选 default，不当测值主存放） | 声明有哪些键、类型、是否必填 |
| **场景上的值树** | **有值** | `inSeed`（或等价）：开跑灌进运行时 `in` |

形状怎么拆（HTTP / 子流入口）：

- **body**：字段树（可嵌套；必填、类型等）  
- **query / header**：轻量参数表（name / type / required / remark…），**不写测值**——与 HTTP 工作台 Kv 行、资产参数行同思路，契约侧只留名与约束  
- HTTP 入口（开放入站）：请求里的真实 query/header/body 按形状校验并注入 `in`；场景值树只服务**场景入口**开跑  

场景入口：形状可提示人填什么；**值只存在场景值树**里。  
出参仍**不**要求入口再声明响应字段树。

**字段 `type`**：不新开一套枚举。各面沿用现有词表即可——入参契约侧现有 `GraphInputField`（string / number / boolean / json…）；若场景表单复用 Input 节点控件则跟 `InputFieldTypes`（text / number / boolean / select…）。缺省仍按各面现逻辑（多当字符串）。出参不强制带类型的字段树。

## 5. 三种一等入口

### 5.1 场景入口

- **场景列表挂在本入口上**（每入口一份子集：环境 + `inSeed` 值树）；入口之间可重复配同类场景，不设流级共用大表。  
- 入参形状提示（无值，可与 HTTP/子流共用声明思路）；开跑用所选场景的值树灌 `in`。  
- 不 HTTP 写出；成败看步骤 / 断言。  
- **不要求** `return`；若有，定稿的 `out` 仅 Run 详情可见。  
- 可选入口说明。

### 5.2 子流入口

- **只声明入参**（树 + 必填），**不声明回法表**。  
- 父节点 `inputs` 映射灌入后从该入口起步（入参侧仍可映射；**出参侧不要 `outputs`**）。  
- 图校验：整次 Run **恰好一次** `return`（IF 各臂可各画一个；真并行域至多一臂带 return）。  
- 执行到 `return`：定稿并**立刻**把 `out` 整包挂到父 `nodes.<子流节点id>.out`（**只要执行到 return 就挂**，含失败后继续才摸到 return；未执行到则不挂）。  
- 子图曾业务失败 → 父步骤 / 子 Run **仍失败**（挂了 `out` 也不改成败）。  
- 父侧在子流节点后断言失败：同理，挂载已发生，Run 可记失败。  
- **不**读子图 `flowOutputs`，**不**双读旧父 `outputs`。  
- 嵌套上限仍 **2** 层。

### 5.3 HTTP 入口

- **有 HTTP 入口 = 已开放入站**；不再要 1.0 的 `open` 布尔。人跑 / CI 走**场景入口**，不靠把 HTTP 入口关掉。  
- method + path、环境、请求 format（入站解析用）。  
- 入参**形状无值**：body 字段树 + query/header 轻量参数表；运行时值来自**入站请求**（按形状注入 `in`）。  
- **不**在入口上做平台鉴权 / 自动 401；要鉴权是**图内业务**（判断 → 组 `out` 含 status 401 → return）。  
- **不**在入口上维护成功/失败响应表；**不**选手填响应 Content-Type（见 §4.0，跟现 `OpenInboundOutFlush`）。  
- 握连接：图合法且能开跑 → 跑图 → **在 `return` 时写出**定稿 `out` → 图可继续断言 → 收束只收尾；否则平台错包（缺登记、图坏、槽满等——不是业务鉴权）。  
- 可选入口说明（给人看）。

```text
请求 → 能开跑？──否──► 平台错包（非业务 401）
         │是
         ▼
      跑图（鉴权若需要：图内分支组 out）→ return：定稿 + 立刻写出 → 断言… → 收束
```

## 6. 运行时分轨

### 6.1 子流

1. 开跑前图须合法（整次恰好一次 return；并行域 / IF 规则见 §2.2）。  
2. 执行到 `return` → 父 `nodes.<子流节点id>.out` = 定稿；**不**摊进父 `flow`、**不**读 `outputs` / `flowOutputs`。  
3. 可含真并行：无 return 的臂照常跑；全部臂结束后再收束；收束不再挂载。  
4. 成败：有业务失败则父步失败；与是否已挂 `out` 无关（见 §6.4）。

### 6.2 开放 HTTP

1. 开跑前图须合法（同上）。  
2. 不能开跑 → 平台错包。  
3. Input 暂停 → 503。  
4. 执行到 `return` → **立刻写出**定稿 `out`；图/并行其它臂可继续；全部结束后收束不再写。  
5. return 后断言失败：响应**已发出**；Run 记失败。

### 6.3 场景

自然结束即可；**不要求** return（零或一次）。  
若有 return：只定稿快照，无对外写出。  
可含真并行；收束前 join。

### 6.4 `alwaysRun`（失败后继续）——一种口径，不拆模式

业务用途：前面挂了，后面标了始终执行的步还想跑（常见：一串子流一次看全）。**不对用户再拆「场景/HTTP/子流三种 alwaysRun 模式」。**

统一规则：

1. 首错后进入失败后继续；未标 `alwaysRun` 的步可 bypass；标了的照跑。  
2. **执行到 `return` 就按 entryKind 交付**（HTTP 写出 / 子流挂载 / 场景快照）——**含**失败后继续才走到的 return；未执行到就不交付。  
3. 整次 Run 仍 **至多/恰好一次 return**（与 §2.2 相同）；失败后继续也不得撞第二个 return。  
4. **成败与交付分离**：只要发生过业务失败，Run / 父步仍记失败；不因已经写出/挂载而改成成功。  
5. 收束：能自然结束（并行则 join）就收束写 Run；开放/子流若整次从未 return → 仍按「缺 return」失败（图校验应尽量先拦）。

造流（含 AI）：不合适就不画 return / 不标 alwaysRun；平台不提供多套开关让用户选「失败后挂不挂」。

## 11. 讨论纪要

- 回法 = **出参 `out`**；返回定稿并按 entryKind 立刻写出/挂载；收束只收尾。  
- **返回节点很瘦**：可选 `label` 即可；**不**挂 `defaultStatus`——缺 `out.status` 只在 **HTTP 写出**补 200；不绑响应表、不做字段树校验、不灌示例。  
- **不要**硬要响应表：开放 HTTP「return 反啥写啥」；子流也不在入口声明回法。  
- **子流合并（已拍板）**：`return` 时整包挂父 `nodes.<子流节点id>.out`；弃父 `outputs` / 子 `flowOutputs`；要字段用 Assign（对称 `nodes.x.http`）。  
- **return 图约束（已拍板）**：整次 Run——开放/子流恰好一次、场景零或一次；**IF 互斥臂可各有 return**；**真并行域静态禁止多臂都带 return**；同序双 return 非法。  
- **真并行（已拍板）**：允许多臂同时跑、各臂可到尽头；收束前 join；不要求每臂都有 return。  
- **立刻写出（已拍板）**：`return` 时按 entryKind 写出/挂载，图继续；收束不再二次写出；其后断言失败不撤回已写出内容。  
- 给人看的说明 = **每入口可选自由文档**，不从流里抽表。  
- 入口节点化；侧栏退役；多入口 + entryKind。  
- 返回默认可继续；路径走尽（并行 join）才收束。  
- **HTTP 唯一键（已拍板）**：`method + path`。  
- **入参形状 vs 值（已拍板）**：入口上 body 树 + query/header 表均为**无值声明**；场景单独**值树**（`inSeed`）；对齐现有 fields / inSeed 分工。  
- **响应 Content-Type（已拍板）**：跟现网——`out.headers` 优先，否则 `application/json;charset=UTF-8`；入口不选手填。  
- **HTTP 入口（已拍板）**：存在即开放，无 `open` 开关；**无**入口级鉴权/自动 401，鉴权只做图内业务。  
- **HTTP status（已拍板）**：写在 `out.status`（图内 Assign）；return 节点不配 `defaultStatus`；HTTP 写出时缺省补 200（跟现网）。  
- **字段 type（已拍板）**：不另立枚举；沿用各面现有类型（`GraphInputField` / Input 节点等）。  
- **入口说明（已拍板）**：挂入口节点；多套靠切换看；分享深链只前期考虑、本次不做。  
- **多场景入口（已拍板）**：每入口自带场景子集，不流级共用大列表。  
- **新建流（已拍板）**：完全空白，不预置入口；用户自己拖。  
- **OpenAPI（已拍板：不做）**：用不到；发对接材料复制入口说明，或 MCP/AI 读图。  
- **MCP（已拍板）**：只暴露 2.0 入口/返回/`out` 等；不兼容旧 `flowOutputs` / `open` 等，不双写。  
- **alwaysRun（已拍板）**：一种口径——执行到 return 就交付（失败后继续亦然）；成败与交付分离；不拆多模式。  
- **最小图示例（已补）**：见 §13（场景-only、HTTP+return）。  
- **`run.trigger`（已拍板）**：首版就要；与 entryKind 正交；收束仍只看 entryKind。枚举见 §2.1.0。  
- **无数据迁移（已拍板）**：Flyway 重做 2.0 基线；不热升 1.x、不迁旧图；种子/模板按 2.0 重写。  
- **发布切口（已拍板）**：**2.0.0 = 流契约 + 插件同发大更新**；`wip/flow-input-spec` 不当主线；批内可并行，tag 前一流一插件一起上。

## 13. 附录：最小合法图 JSON 示意

> 示意用，字段名以落地实现为准；**无** 1.0 `flowOutputs` / `open` / 父 `outputs`。  
> 仅两条：场景（可不 return）、HTTP（须 return 并立刻写出）。

### 13.1 场景-only（人跑 / CI）

`scenario-entry` → HTTP 业务一步 → 尽头。无 return 合法。

```json
{
  "nodes": [
    {
      "id": "e-sc",
      "type": "scenario-entry",
      "position": { "x": 0, "y": 0 },
      "data": {
        "name": "默认场景入口",
        "doc": "",
        "scenarios": [
          {
            "id": "sc1",
            "name": "冒烟",
            "testProjectEnvId": "<envId>",
            "inSeed": {}
          }
        ]
      }
    },
    {
      "id": "n-http",
      "type": "http",
      "position": { "x": 240, "y": 0 },
      "data": {
        "name": "调用被测接口",
        "apiId": "<apiId>"
      }
    }
  ],
  "edges": [
    { "id": "ed1", "source": "e-sc", "target": "n-http" }
  ],
  "meta": {}
}
```

开跑：`entryKind=scenario`，`entryNodeId=e-sc`，`trigger` 如 `ui`/`ci`/`suite`/`mcp`；选场景 `sc1` 灌 `inSeed`；走到 `n-http` 无后继 → 收束写 Run。

### 13.2 HTTP 开放（须 return）

`http-entry` → Assign 组 `out` → `return`（立刻写出）→ 可选断言 → 尽头。

```json
{
  "nodes": [
    {
      "id": "e-http",
      "type": "http-entry",
      "position": { "x": 0, "y": 0 },
      "data": {
        "name": "退款入站",
        "method": "POST",
        "path": "/v3/refund",
        "runEnvId": "<envId>",
        "doc": "开放退款入站说明（可选）",
        "inputShape": {
          "body": [
            { "name": "orderId", "type": "string", "required": true }
          ],
          "query": [],
          "headers": []
        }
      }
    },
    {
      "id": "n-assign",
      "type": "assign",
      "position": { "x": 240, "y": 0 },
      "data": {
        "name": "组出参",
        "assignments": [
          {
            "scope": "out",
            "name": "status",
            "op": "set",
            "value": 200
          },
          {
            "scope": "out",
            "name": "body",
            "op": "set",
            "value": { "ok": true }
          }
        ]
      }
    },
    {
      "id": "n-ret",
      "type": "return",
      "position": { "x": 480, "y": 0 },
      "data": {
        "label": "成功回包"
      }
    },
    {
      "id": "n-assert",
      "type": "assert",
      "position": { "x": 720, "y": 0 },
      "data": {
        "name": "回包后校验（可选）",
        "assertions": []
      }
    }
  ],
  "edges": [
    { "id": "ed1", "source": "e-http", "target": "n-assign" },
    { "id": "ed2", "source": "n-assign", "target": "n-ret" },
    { "id": "ed3", "source": "n-ret", "target": "n-assert" }
  ],
  "meta": {}
}
```

开跑（入站）：`entryKind=http`，`entryNodeId=e-http`，`trigger=http`；请求注入 `in` → Assign → **return 立刻写出** → assert → 收束（不再写）。缺 `out.status` 时写出路径补 200。
