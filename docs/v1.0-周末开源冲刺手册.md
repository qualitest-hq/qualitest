## B. Cursor 自动测试（Agent 逐步清单）

> 由 **Agent + IDE Browser MCP**（及可选 qualitest MCP）代点、代查。打勾：Agent 跑通或你亲自点过。失败记 §F。  
> 业务提示正文以 [ai-test-flow-prompts.md](../../qualitest-demo/docs/ai-test-flow-prompts.md) 为准；下表只列场景 ID + 意图 + 期望，避免双份漂移。

### B.0 分工与硬规则

| 谁 | 负责 |
|----|------|
| **你** | 起服务；插件上传接口；验证码 / 确认框；可选 RustFS / LLM Key |
| **Agent** | 浏览器代点、截图、调 MCP、按 T1→T2→T3 验收并填结果；**发现产品 bug 则修代码后人可复现重测** |
| **半自动 / 可跳过** | LLM Key、qualitest MCP Token、RustFS、Compose 一键栈 |

**Agent 必须遵守**

1. 先确认端口再开浏览器；连不上就停，不空转。  
2. 每小步：`browser_take_screenshot`（或等价）+ 标明 **通过 / 失败 / 跳过**。  
3. iframe 点不到 → 记阻塞，改走 Swagger / curl / 调试台（仅作该步诊断；**T2 画布项仍须画布过**）。  
4. 开启「允许还原被测数据」后：**同一环境串行跑**。  
5. 写库场景前先加载对应场景（demo-ui 或 `POST /web/test/scenario/load/{id}`）。  
6. 同一操作连续失败 ≥4 次 → 停手汇报。  
7. 改画布走 Web **AI 助手 → Staging 确认 → 保存**；qualitest MCP **只读**。  
8. **严格遵守 §B.0.1**（人可复现）；违反则该条勾选作废。

浏览器工具顺序：`browser_tabs` → `navigate` → `lock` → 交互 → 关键步 snapshot/截图 → 结束 `unlock`。  
质衡 MCP 可并行：查 `testFlowId` / 失败现场；浏览器改画布与点 Run。

| 档 | 范围 | 是否必须 |
|----|------|----------|
| **T1** | 登录 → 环境 → 调试 → S01 → 一条购物流 Run | **必须**（开源门禁） |
| **T2** | Demo 全业务（S01–S08 / F01–F12），**优先画布测试流** | 尽力；不挡公开 |
| **T3** | 媒体 / 快照 / AI / MCP / Compose | 可选 |

### B.0.1 人可复现测试铁律（重点）

> **目的**：冒烟要证明「真人用户按产品 UI 能走通」；Agent 只是代点。若用控制台改 store、直接改库、或只调 demo API 刷绿，**对开源验收没有意义**，还会掩盖产品 bug。

#### 允许（人手也能做）

| 动作 | 说明 |
|------|------|
| 浏览器点击 / 输入 / 选场景 / 保存 / Run | 有头浏览器，用户可盯着看 |
| 质衡 **AI 助手** 发提示 → Staging 逐项 **✓ 确认 / ✕ 取消** → 保存 | 与真人造流同一路径 |
| demo-ui 或管理 API **加载 / reset 场景** | 产品提供的测试支撑，人手也会点 |
| 调试台逐步调接口 | 人手可用；可作诊断，**不能单独当作 T2「画布流」勾选依据** |
| 修 **产品代码 / SQL 种子 / 文档** 后，再按上表重测 | 正规闭环 |
| 截图、Run 详情、§F 记现象 | 证据 |

#### 禁止（人手做不到或等于作弊）

| 禁止 | 反例（本周末已踩过，勿再犯） |
|------|------------------------------|
| `page.evaluate` / 控制台改 **Pinia / Vuex / 内存图** | 拒幽灵边、改 `pendingEdges`、直接 `markConfirmed` |
| 直接 **UPDATE 库里的 `graph_json` / 跑批 SQL「修图」** 冒充 UI 造流成功 | 除非用户明确要求修数据脚本，且仍须 UI 重跑验收 |
| 用 **curl/脚本只打 8081** 勾选 T2 画布相关项 | API 绿 ≠ 画布/Staging/Run 绿 |
| 为过断言 **悄悄改断言期望或跳过节点** 却不修引擎/不记 §F | 掩盖缺陷 |
| 点击被侧栏挡住仍 `force` 点、用户看不见的「幽灵操作」当成功 | 应平移画布 / 缩放，使人也能点到 |

#### 卡住时怎么做（正规顺序）

```text
1. 截图 + 写清：UI 上人手下一步会点什么、点了发生什么
2. 判断：操作问题（没找到按钮） vs 产品缺陷（点了也不对 / 无法完成）
3. 产品缺陷 → 修代码（或记 §F 阻塞）→ 重启如需 → 从同一 UI 步骤重试
4. AI 造流出错（幽灵 start 边、非法断言运算符、不支持的 JsonPath）→
   用人可点的方式：Staging ✕ 取消坏项 / 让 AI「修复本节点或重生成」/ 属性面板改规则
   → 禁止用 store 手术让边「假装」灌进画布
5. 简单 bug 直修；复杂先写方案文档再改（例：完整 JsonPath → docs/flow-jsonpath-方案.md）
```

#### T2 / 画布项勾选口径

- **可勾**：该用例对应测试流在质衡画布上 **Staging 已清零（若有）→ 已保存 → Run 终态符合期望**，证据含截图或 Run 时间。  
- **不可勾**：仅 demo API / Swagger / 临时脚本通过。可在备注写「API 曾绿，画布未验」。  
- **推荐造流**：提示集对应段落 → AI 助手生成 → 用户（或 Agent 代点）确认 → Run；顺带测画布与 AI Staging。

#### 可复制给 Agent 的提示词

```text
你正在执行 qualitest《v1.0-周末开源冲刺手册》的自动测试。必须遵守手册 §B.0.1：

1. 只用真人在产品 UI 上也能完成的操作验收（浏览器点击、AI 助手、Staging 确认/取消、保存、Run、场景加载）。
2. 禁止：改 Pinia/内存状态、直接改 graph_json 刷绿、用仅调 demo API 的结果勾选画布相关用例、force 点击被遮挡且用户看不见的控件当成功。
3. T2 画布相关项：必须「场景加载 →（AI）造流或打开流 → Staging 确认干净 → 保存 → Run → 断言符合期望」；仅 API 绿不得勾选。
4. 发现产品缺陷：先记 §F，能修则改产品代码并用人可复现路径重测；不要用旁路数据手术绕过。
5. AI 生成坏图（如连到不存在的 start、notempty/非法 JsonPath）：用 Staging 取消、AI 修复提示或属性面板修改；不要 evaluate 修 store。
6. 每步截图；连续同操作失败 ≥4 次停手汇报；结果按 §B.5 汇总。

从手册当前断点继续；已勾选且证据不足的项应改回未勾或注明作废重测。
```

#### 与工程修复的边界

| 类型 | 做法 |
|------|------|
| 冒烟发现的产品 bug | 修代码 → UI 重测 → §F 记关闭 |
| 能力缺口（如完整 JsonPath） | 先方案文档，**一次做完**；合入前该项可暂记 §F / 改写断言用人可支持的语法做临时验收（须在备注标明「引擎能力待 JsonPath」） |
| 靶场种子 / 缺列 | 可改 SQL 种子或 patch（人手部署也会做）→ reset 场景 → 再 UI 测 |
