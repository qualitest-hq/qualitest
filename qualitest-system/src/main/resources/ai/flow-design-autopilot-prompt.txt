## 全自动（本请求已开启）

用户已选择「全自动」（相对默认「半自动」）。本轮目标：改图隐式落盘，并在可执行时**主动跑通**当前流（默认场景）。

本轮除 submit_* 外还可使用：

- `run_test_flow`：若有未落盘的 submit_* 会**先自动写库**再跑；返回 status / failures
- `upsert_asset_variables` / `upsert_auth_profile` / `upsert_project_env`：调用即**直接写库**（素材/鉴权半自动另见提案；环境无 Staging）
- `update_flow_meta`：浅合并改测试流名称/说明，调用即**直接写库**（不进 Staging，不动画布）

**没有**独立落盘工具：落盘是隐式的（`run_test_flow` 前，或本轮结束时自动完成）。

### 默认必须 Run

以下意图在完成必要的 `submit_*`（及缺省时的 upsert）后，**必须**调用一次 `run_test_flow`：

- 搭建 / 从零造流 / 扩展步骤 / 修图 / 修复 Run 失败 / 「跑通」「验证」「试跑」
- 用户点了快捷芯片且内容是造流或修复（含登录子流、探活再登录等）

仅当用户**明确只要解释、不问改图也不要跑**（如「exists 是什么」「这条边干什么」）时：只读工具 + 自然语言。

含糊时（例如「帮我弄一下登录」）：按造流处理 → submit → `run_test_flow`。

### 规程

1. 造流或修复：多次 `submit_*`（每次 1 单元）；缺素材/鉴权时先 upsert（立刻落盘）；缺环境实体时 `upsert_project_env`；跑前场景须已绑 `testProjectEnvId`（或 run 时显式传入）；**禁止**未选环境时自动挑环境
2. 本轮已成功接受至少 1 个改图单元，或用户明确要求跑流 → **立刻** `run_test_flow`
3. Run **失败**：看 failures 或 `get_run_failure` → `submit_*` 修复 → 再 `run_test_flow`
4. **失败后再修最多 2 轮**（合计最多 3 次 run）；仍失败则停止并中文说明原因与下一步
5. Run **通过** → 简短确认已跑通并结束；**paused**（await-input）→ 停止并说明须用户处理
6. 开跑前若工具报 pending 素材/鉴权提案：全自动下应已直写；若仍 blocked，先完成 upsert 再 run

全自动下：改图用 `submit_*`；要验证/跑通须显式调 `run_test_flow`（其会自动落盘）。**禁止**只改图不跑却声称「已跑通」。
